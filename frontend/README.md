# MyCollection frontend

React + TypeScript + Vite. Фронтенд находится рядом с существующим Spring Boot приложением, в отдельной папке `frontend`.

## Запуск

Зависимости уже установлены в рабочей папке. На этом компьютере достаточно запустить `frontend/start.cmd`, затем открыть http://127.0.0.1:5173. Скрипт использует установленный Node.js или встроенный Node.js Codex. Остановка — Ctrl+C в его окне.

Нужны Node.js 22.12+ и pnpm 11+ (либо npm). В каталоге `frontend`:

```powershell
pnpm install
pnpm dev
```

Альтернатива: `npm install` и `npm run dev`. Открыть http://127.0.0.1:5173.

Spring Boot запускается отдельно из корня проекта на Java 25:

```powershell
.\mvnw.cmd spring-boot:run
```

Сервер использует существующий `.env` и PostgreSQL. Для регистрации в справочнике ролей должна присутствовать `ROLE_USER`, как предусмотрено текущим `CustomUserDetailsService`. Vite перенаправляет `/api/*` на `http://127.0.0.1:8080/*`. Для другого адреса скопируйте `.env.example` в `.env.local` и измените `API_PROXY_TARGET`.

## Что подключено

| Действие | API Spring Boot |
| --- | --- |
| Регистрация | `POST /registration` |
| Вход | `POST /auth` |
| Загрузка текущего пользователя и профиля | `GET /user/me` |
| Создание профиля | `POST /registration/create_profile` |

После регистрации выполняется вход, затем пользователь попадает в профиль. Имя и описание профиля сохраняются в базе. Существующий профиль загружается после повторного входа и обновления страницы. В шапке вместо входа и регистрации показывается кнопка «Профиль» с иконкой.

`GET /user/me` добавлен для получения данных по проверенному JWT. Создание профиля теперь требует JWT, проверяет владельца и отклоняет повторное создание (409). Клиент передаёт `userId` из ответа `/user/me`. Репутация берётся с сервера. Поля аватара и местоположения передаются как `null`: API загрузки файлов и справочника мест ещё нет, технические идентификаторы не выводятся в форму.

Токен хранится в `sessionStorage` текущей вкладки, пароль не сохраняется. Выход удаляет токен. Истечение JWT и ответ 401 завершают сессию. Существующая настройка сервера `jwt.app.lifetime=60000` задаёт срок **60 секунд**; при необходимости увеличьте её, например до `1h`. Автоматическое обновление токена не реализовано, поскольку refresh API отсутствует.

## Демонстрационная часть

Главная основана на требованиях 08, 21–28: смешанная лента, категории, поиск, фильтр типа материала, сортировка, стрелки голосования и подборки коллекций. Профиль следует требованиям 02–03 и 32–33: отображаемое имя, описание, репутация, разделы коллекций, публикаций и отзывов.

Лента, топы, объявления и аукционы используют явно обозначенные примеры из `src/data.ts`. Голоса и закладки действуют только до ухода со страницы и не отправляются на сервер. Рейтинги демонстрационные; персональные рекомендации пока не рассчитываются. Публикация материалов, комментарии, сделки, торги, восстановление пароля, редактирование профиля, выбор тематик и загрузка аватара требуют следующих серверных API. В интерфейсе нет кнопок, имитирующих успешное выполнение этих операций.

Иллюстрации монет, марок, пластинки и фотоаппарата выполнены CSS и не являются фотографиями или точными историческими репродукциями. Для шрифта Golos Text используется Google Fonts, при недоступности сети — системный шрифт.

## Проверки

```powershell
pnpm test
pnpm build
```

Тесты интерфейса в jsdom проверяют контракты запросов, регистрацию → вход → создание профиля, выход, отклонённую сессию, ошибки сети, несовпадающие пароли, восстановление после частично успешной регистрации, поиск и переключение голосов. Ответы API в этих тестах подставные.

Интеграционные тесты из корня проекта запускают настоящий Spring Boot, Security и JPA с отдельной H2-базой в памяти:

```powershell
.\mvnw.cmd -Dtest=AccountFlowIntegrationTests test
```

Проверяют регистрацию, JWT-вход, создание и повторное чтение профиля, повторное создание, запрет создания чужого профиля, отсутствие авторизации и некорректный JWT. PostgreSQL пользователя эти тесты не используют. Старый `AppApplicationTests` остаётся отдельным тестом контекста с исходными настройками окружения.

## Сборка для размещения

`pnpm build` создаёт `dist`. Хостинг должен отдавать `index.html` для маршрутов React (`/login`, `/register`, `/profile` и др.) и проксировать `/api/*` на Spring Boot с удалением `/api`. Настройка `server.proxy` работает только при разработке. При размещении API на другом адресе задайте `VITE_API_BASE_URL` во время сборки и настройте CORS на сервере. Секретов в переменных `VITE_*` быть не должно.

Ничего не публиковалось во внешние сервисы.
